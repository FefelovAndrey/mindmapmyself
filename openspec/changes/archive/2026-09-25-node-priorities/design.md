# Design

## Context

См. `proposal.md` — Why. Сейчас у узла нет приоритета. Фильтры «Ответственный» и «Статус» — один выпадающий список с галочками на Outline и карту. Совпадение внутри списка — «или», между списками — «и». Несовпавший узел скрыт, предки совпадения остаются, номера не пересчитываются (`filterTree` / `isNodeVisibleInFilter`). Карточка справа уже сохраняет статус через общий автосейв. Старые карты читаются схемой, которая дописывает отсутствующие поля.

## Goals / Non-Goals

**Goals:**

- Поле приоритета в документе карты, обратно совместимое чтение.
- Один список фильтра по тому же правилу, что статус, плюс значение «без приоритета».
- Цифра перед именем в Outline и в шапке карточки на карте; заливка только у 1.

**Non-Goals:**

- См. `proposal.md` — Non-goals. Отдельного слоя сортировки и наследования нет.

## Decisions

1. **Поле `priority: 1 | 2 | 3 | null`.** В схеме отсутствующее поле становится `null`, как календарные поля. Значение вне 1–3 отклоняется при сохранении. Альтернатива — строка `"high"|"medium"|"low"`: в интерфейсе уже договорена цифра, число совпадает с тем, что видит пользователь.

2. **Фильтр хранит строки `'1' | '2' | '3' | 'none'`.** Существующий список с галочками принимает только строки. Пустой массив — все узлы. `'none'` совпадает только с `priority === null`. Остальная логика предков не переписывается, в неё добавляется третье условие «и».

3. **Отображение — бейдж, не отдельная строка.** В Outline бейдж стоит между номером и именем, не в ряду статуса. На карте — в шапке рядом с номером, без новой строки и без роста высоты карточки. У 1 бейдж залитый и лёгкий фон строки/карточки цветом, отличным от New / Done / Cancelled. У 2 и 3 — контур. Пустой приоритет не рисуется.

4. **Новый узел получает `priority: null` в том же месте, где сейчас `status: 'New'`.** Импорт mmap тоже пишет `null`. Приоритет родителя не читается.

5. **Проверка.** Jest — совпадение фильтра, «или» внутри приоритета, «и» со статусом и ответственным, видимость предков, узел без приоритета. Сценарии из `specs/node-priorities/spec.md` человек проходит в браузере. Сборку типов гоняет `npm run build`.

## Risks / Trade-offs

- [Заливка приоритета 1 спорит со стилем Done/Cancelled] → фон приоритета слабее бейджа статуса; бейдж Done остаётся в строке. Сценарий «Приоритет 1 у узла со статусом Done» это проверяет.
- [Старый JSON без поля] → чтение подставляет `null`, файл не переписывается, пока пользователь сам не сохранит карту.
- [Длинное имя в Outline] → бейдж приоритета не сжимается, имя по-прежнему занимает оставшуюся ширину.

## Migration Plan

Отдельной миграции нет. Откат кода: схема по-прежнему отбрасывает незнакомое поле, сохранённый `priority` не ломает чтение старой версией.
