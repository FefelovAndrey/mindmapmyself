# Design

## Context

См. proposal.md — Why. Сейчас `responsible` — строка или `null` на узле. Варианты фильтра собирает обход дерева (`collectResponsibles`). Документ карты — `version`, `updatedAt`, `root` в `data/mindmap.json`, схема `MindMapDocumentSchema`. Вкладки редактора: Outline и Карта.

## Goals / Non-Goals

**Goals:**

- Один массив имён в документе, рядом с деревом.
- Старые файлы без массива открываются: имена с узлов становятся списком.
- Переименование правит список и уже назначенные узлы. Неактивность не стирает имя с узлов и закрывает его для нового выбора.
- Логику списка покрывает Jest. Сценарии из спеки проверяет человек в браузере.

**Non-Goals:**

- Несколько имён на одном узле.
- Отдельный API справочника. Список едет в том же документе и том же автосохранении.

## Decisions

1. **Поле `responsibles` на документе: имя и признак активности, не вывод из дерева.** Иначе нельзя хранить человека, которого ещё никуда не назначили, и нельзя отличить неактивного от отсутствующего. Альтернатива — вычислять список только из узлов: она не закрывает экран наполнения и неактивность.

2. **Чтение старого файла.** Если поля нет, схема подставляет имена, собранные с узлов, без дублей, по алфавиту, все активные. Повторное сохранение записывает поле. Узел по-прежнему хранит одно имя строкой.

3. **Правки списка — чистые функции.** Добавление, переименование и смена активности возвращают новый документ. Удаления нет. Переименование заменяет имя на узлах. Неактивность дерево не чистит. Пустая строка и дубль не меняют документ и дают причину для текста на экране. Jest проверяет эти функции, не вёрстку.

4. **Вкладка, не отдельная страница.** Третий режим рядом с Outline и Картой. Карточка узла в этом режиме не нужна: на вкладке только список.

5. **Карточка узла.** Текстовое поле заменяется на список: «не указан» и активные имена. Если на этом узле уже стоит неактивный человек, его имя остаётся выбранным значением, но в список для других узлов не попадает. Поля «добавить сотрудника» в карточке и в Outline нет.

6. **Фильтр.** Варианты берутся из справочника, включая неактивных, а не из обхода дерева. Правила отбора узлов не меняются.

## Risks / Trade-offs

- [Неактивный остаётся на уже назначенных узлах] → Так и задумано: выбор закрыт, история узла не стирается. Снять человека можно вручную через «не указан».
- [Имя на узле, которого нет в списке, после ручной правки JSON] → При разборе документа такое имя добавляется в список, узел не обнуляется.
- [Один документ на всё автосохранение] → Правка списка и правка узла делят одну очередь сохранения. Отдельной гонки между двумя API нет.

## Migration Plan

Отдельного скрипта нет. Первый разбор старого `mindmap.json` достраивает `responsibles`. Откат — не читать поле и снова собирать имена с узлов; уже переименованные узлы останутся с новым текстом.

## Open Questions

Нет. Неактивность вместо удаления и правило «один человек на узел» зафиксированы в proposal и спеке.
