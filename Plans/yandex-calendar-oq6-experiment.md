# План эксперимента OQ-6 / OQ-7

**Цель:** выяснить, как Яндекс Календарь в CalDAV отличает **событие типа «Задача»** от **«Встреча»**, и как читать признак **«выполнена»**.  
**Связь:** BRD v1.1, блокер реализации create/sync.  
**Эталон UI:** диалог «Новое событие» → вкладка «Задача», календарь «Мои события».

**Успех эксперимента:** таблица «свойство → значение» + минимальный `PUT`, после которого в веб-UI запись открывается как **Задача**, не как Встреча и не как элемент `todos-*`.

---

## 0. Подготовка (15–30 мин)

1. В `.env.local` (не в git):
   - `YANDEX_CALENDAR_EMAIL`
   - `YANDEX_OAUTH_TOKEN` (scope `calendar:all`)
   - `YANDEX_EVENTS_CALENDAR_ID` (например `events-35737546`)
2. Проверить доступ:
   ```bash
   curl -s -X PROPFIND "https://caldav.yandex.ru/calendars/${EMAIL}/" \
     -H "Authorization: OAuth ${TOKEN}" \
     -H "Depth: 1" -H "Content-Type: application/xml" \
     --data '<?xml version="1.0"?><d:propfind xmlns:d="DAV:"><d:prop><d:displayname/></d:prop></d:propfind>'
   ```
3. Зафиксировать URL коллекции событий:  
   `https://caldav.yandex.ru/calendars/<email>/<events-id>/`
4. Удобно иметь рядом открытый [calendar.360.yandex.ru](https://calendar.360.yandex.ru/) под тем же аккаунтом.

## 1. Эталон «из UI» (чтение, без PUT)

**Идея:** сначала посмотреть, что Яндекс сам пишет в `.ics`, когда пользователь создаёт запись руками.

| Шаг | Действие | Результат записать |
|-----|----------|-------------------|
| 1.1 | В UI: «Новое событие» → **Встреча** → название `EXP-MEETING-001`, завтра 10:00–11:00, календарь «Мои события» → Создать | UID / ссылка |
| 1.2 | В UI: «Новое событие» → **Задача** → название `EXP-TASK-001`, завтра 12:00–13:00, тот же календарь → Создать | UID / ссылка |
| 1.3 | Опционально: задача из списка задач (`todos`), название `EXP-VTODO-001` | чтобы убедиться, что это **другой** путь |
| 1.4 | Через CalDAV `REPORT` / `GET` скачать оба (три) `.ics` | сырой текст |
| 1.5 | Diff `EXP-MEETING` vs `EXP-TASK` | список отличающихся свойств |

**Как найти объект после создания в UI:**
- `REPORT` `calendar-query` по диапазону дат эксперимента; или
- экспорт / поиск по `SUMMARY:EXP-TASK-001`.

**На что смотреть в diff (чеклист):**

- `CATEGORIES`, `CLASS`, `STATUS`, `TRANSP`
- все строки `X-…` / `X-YANDEX-…` / `X-MICROSOFT-…`
- `PRIORITY`, `PERCENT-COMPLETE`, `COMPLETED` (если вдруг есть у VEVENT)
- наличие/отсутствие `ATTENDEE`, `LOCATION`, `X-TELEMOST-*`
- одинаковый ли `BEGIN:VEVENT` у обоих (ожидаем да для встречи и задачи-события)
- у `EXP-VTODO-001` — ожидаем `BEGIN:VTODO` и коллекцию `todos-*`

**Выход шага 1:** гипотеза вида  
«тип Задача = свойство `X-FOO:BAR`» (или набор свойств).

## 2. Проверка «выполнена» (OQ-7)

На событии-задаче из UI:

| Шаг | Действие |
|-----|----------|
| 2.1 | Отметить `EXP-TASK-001` выполненной в веб-UI |
| 2.2 | Снова `GET` того же `.ics` |
| 2.3 | Diff до/после: какое поле появилось/изменилось (`STATUS`, `COMPLETED`, `PERCENT-COMPLETE`, `X-…`) |
| 2.4 | Снять выполнение выполнения → ещё один `GET` → что откатывается |

**Выход шага 2:** правило для sync Done в BRD (AC-3.3).

## 3. Синтез через CalDAV (запись)

Цель — повторить UI только через API.

| Шаг | Действие | Критерий |
|-----|----------|----------|
| 3.1 | `PUT` минимальный VEVENT **без** найденного маркера (как обычная встреча), `SUMMARY=EXP-PUT-MEETING` | В UI = **Встреча** |
| 3.2 | `PUT` тот же шаблон **+** кандидат-маркер из шага 1, `SUMMARY=EXP-PUT-TASK` | В UI = **Задача** |
| 3.3 | Если 3.2 не сработал — перебор кандидатов по одному (не пачкой) | Найти минимальный достаточный набор |
| 3.4 | `PUT` с маркером задачи, но в путь `todos-*` (негативный контроль) | Не наш целевой сценарий; зафиксировать отличие |

Шаблон PUT (подставить маркер после шага 1):

```text
BEGIN:VCALENDAR
VERSION:2.0
PRODID:-//MindMap//OQ6//RU
BEGIN:VEVENT
UID:<uuid>
DTSTAMP:<utc>
DTSTART;TZID=Asia/Yekaterinburg:20260822T120000
DTEND;TZID=Asia/Yekaterinburg:20260822T130000
SUMMARY:EXP-PUT-TASK
DESCRIPTION:oq6
<СЮДА_МАРКЕР_ТИПА_ЗАДАЧА>
END:VEVENT
END:VCALENDAR
```

**Критерий приёмки эксперимента (не приложения):**  
открыть `EXP-PUT-TASK` в UI → вкладка/тип **«Задача»**, календарь «Мои события».

## 6. Риски

| Риск | Что делать |
|------|------------|
| Маркер только на стороне UI, CalDAV пишет «голый» VEVENT | Сравнить GET сразу после UI-create; если идентичны встрече и задаче — эскалация: тип не различим по CalDAV → менять AC / UX приёмки |
