# BRD — Map View (простая схема)
## Mind Map Editor — вкладка «Карта»

**Версия:** 1.0  
**Дата:** 23.06.2026  
**Статус:** согласовано с заказчиком  
**Родительский документ:** `requirements/BRD.md` (v1.0 — outline, карточка, фильтры)

---

## 1. Контекст и цель

В v1.0 реализован режим **Outline** (дерево-список) и карточка атрибутов. Требуется добавить второй вид — **простую схему слева направо** для обзора структуры задач RULI без радиальной раскладки MindManager.

**Цель:** дать пользователю визуальный обзор иерархии на одних и тех же данных, что и в Outline, с выбором узла и синхронизацией с карточкой атрибутов.

**Не цель:** заменить Outline, воспроизвести полный UI MindManager, редактирование на карте.

---

## 2. Режимы интерфейса

| Режим | Назначение |
|-------|------------|
| **Outline** | редактирование структуры и названий (как в BRD v1.0) |
| **Карта** | просмотр структуры, выбор узла |

- Переключение — **вкладки** в верхней части панели дерева (или эквивалентный tab-switcher).
- Активная вкладка сохраняется в рамках сессии (localStorage — опционально, не обязательно в v1.0).
- Карточка атрибутов (`NodeCard`) **общая** для обоих режимов: справа, без изменений по поведению BRD v1.0.

## 3. Функциональные требования

### 3.1. Отображение узла на карте

На каждом узле отображаются поля:

| Поле | Источник | Правила |
|------|----------|---------|
| Номер | вычисляется (`calcNumbers`) | как в Outline |
| Наименование | `name` | перенос длинного текста (word-wrap), без обрезки «…» |
| Ответственный | `responsible` | если `null` — не показывать или «—» (единый стиль в UI) |
| Статус | `status` | `New` / `Done` / `Cancelled`; если `null` — не показывать или «—» |

**Не показывать на карте:** описание, срок выполнения (остаются только в карточке).

### 3.2. Раскладка

- Направление: **слева направо** (корень слева, потомки — вправо).
- Связи: прямые линии между родителем и дочерними узлами (орто- или плавные — на усмотрение реализации).
- Узлы — прямоугольные блоки (не радиальная mind map).
- При большом числе узлов (до 500 по NFR родительского BRD) схема должна оставаться navigable за счёт zoom/pan (см. §3.6).

### 3.3. Взаимодействие на карте

| Действие | Поведение |
|----------|-----------|
| Клик по узлу | выбор узла; обновление `NodeCard` |
| Двойной клик | **не** запускает inline-редактирование |
| Enter / Tab / Delete / F2 | **не** обрабатываются на вкладке «Карта» (горячие клавиши Outline — только на вкладке Outline) |
| Drag-and-drop узлов | **вне scope** (отложено) |

Выбранный узел на карте визуально выделяется (как selected в Outline).

### 3.4. Фильтрация

- Фильтры **Ответственный** и **Статус** (`FilterBar`) действуют **и на Outline, и на Карте**.
- Логика совпадает с BRD v1.0:
  - совпадающие узлы — обычное отображение;
  - родители без совпадения — приглушённый вид (контекст иерархии);
  - нумерация — оригинальная, не пересчитывается;
  - «Сбросить» снимает все фильтры.
- На карте при `matchCount === 0` — сообщение «Нет результатов» (аналог Outline).

### 3.5. Сворачивание веток (collapse)

> **Требует решения заказчика** — см. обсуждение в §7 ниже.

До решения: **общее состояние collapsed** для Outline и Карты (один `Set<string>` collapsed id). Свернутая на Outline ветка **не показывает потомков** и на карте.

### 3.6. Навигация по карте

| Функция | Обязательность |
|---------|----------------|
| Zoom (колёсико мыши и/или кнопки +/−) | да |
| Pan (перетаскивание фона) | да |
| «Вместить на экран» (fit all / fit selection) | желательно |
| Прокрутка к выбранному узлу при выборе из Outline | желательно при split-навигации |

---

## 4. Синхронизация состояния

- **Данные:** один источник — `doc.root` из API / автосохранение без изменений.
- **Выбранный узел:** один `selectedId` — выбор в Outline или на Карте обновляет оба вида и карточку.
- **Фильтры:** один `FilterState`.
- **Collapsed:** один набор (пока не решено иное в §3.5).

---

## 5. Нефункциональные требования

- Без интернета (локальное приложение).
- Производительность: до **500 узлов** без заметных лагов при переключении вкладки и pan/zoom.
- Новые npm-зависимости — по результатам выбора библиотеки (§6); предпочтение минимальному набору.
- Стили — CSS Modules, в духе существующих компонентов.

---

## 6. Выбор технологии (на обсуждении)

См. отдельный раздел в переписке / `Decision-MapView.md` после выбора.

Критерии:

- дерево слева направо;
- read-only рендер + клик по узлу;
- zoom/pan;
- без обязательного DnD;
- совместимость с React 19 / Next.js 15.

---

## 7. Вне области (не входит в Map View v1.0)

- Радиальная mind map
- Редактирование на карте (inline, горячие клавиши структуры)
- Drag-and-drop перемещение узлов
- Экспорт карты в PNG/PDF
- Отдельное состояние collapse для карты (до явного решения)
- Показ срока и описания на блоках узла

---

## 8. Критерии приёмки

1. На главной странице есть вкладки **Outline** и **Карта**.
2. На «Карте» отображается дерево слева направо с линиями между узлами.
3. На блоке узла видны: номер, наименование (с переносом), ответственный, статус.
4. Клик по узлу выбирает его; карточка справа показывает атрибуты выбранного узла.
5. Фильтры работают на карте так же, как в Outline.
6. Работают zoom и pan.
7. Редактирование структуры по-прежнему только в Outline; автосохранение JSON без регрессий.
