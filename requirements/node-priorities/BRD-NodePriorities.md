## 1. Цель

Дать возможность явно помечать узлы приоритетом по шкале **1–3**, где **1 — самый важный**, а 3 — наименее важный из заданных уровней. Это нужно, чтобы в большом дереве задач быстро видеть, что требует внимания в первую очередь, и сосредоточиться на нужных ветках.

Пользователь должен уметь **задавать** приоритет в карточке узла, **видеть** его в Outline и на карте и **фильтровать** дерево по одному или нескольким уровням приоритета — так же, как сейчас работают фильтры по ответственному и статусу.

**Не цель (v1):**
- автоматический расчёт приоритета по сроку или статусу;
- наследование приоритета от родителя к дочерним узлам;
- сортировка всего дерева или siblings по приоритету;
- шкала шире трёх уровней (4, 5, «критический» и т.п.).

## 3. Шкала приоритетов

Числовая шкала: меньшее значение = выше приоритет.

| Поле | Тип | Диапазон | По умолчанию |
|------|-----|----------|--------------|
| `priority` | `number \| null` | **1–3** (1 = самый важный) | `null` |

| Значение | Подпись в UI | Смысл |
|----------|--------------|-------|
| `1` | **1** (или «Высокий» — уточнить в FR-2) | самый важный |
| `2` | **2** (или «Средний») | средний |
| `3` | **3** (или «Низкий») | наименее важный из трёх |
| `null` | `— не указан —` | приоритет не задан |

### FR-3. Фильтрация по приоритету

**Где:** `FilterBar`, рядом с фильтрами «Ответственный» и «Статус».

**Поведение:**
- режим выбора: _[мультивыбор / один приоритет / мультивыбор + «без приоритета»]_
- логика с другими фильтрами: **AND** (как сейчас: ответственный **и** статус **и** приоритет)
- внутри фильтра «Приоритет»: **OR** между выбранными значениями _(если мультивыбор)_
- при активном фильтре: совпадающие узлы выделены; родители без совпадения — приглушённые (как в BRD v1.0)
- нумерация при фильтрации **не пересчитывается**
- кнопка «Сбросить» снимает **все** фильтры, включая приоритет
- счётчик совпадений (`matchCount`) учитывает приоритет

**Пустой результат:** сообщение «Нет результатов» — как сейчас.

### FR-4. Модель данных

| Поле | Тип | Смысл |
|------|-----|--------|
| `priority` | `number \| null` | приоритет узла (1–3); `null` = не задан |

**Миграция / обратная совместимость:**
- старые JSON без `priority` загружаются без падения → трактовать как `null`;
- импорт `.mmap` → `priority: null`;
- новые узлы (`newNode`) → `priority: null`.

**Zod / API:** поле добавляется в `MindNodeSchema` и сохраняется в `mindmap.json` через `POST /api/nodes`.

## 5. Нефункциональные требования

- Приоритет — часть локального JSON, без внешних API.
- Производительность фильтрации на дереве до **500 узлов** — без заметных лагов (как текущие фильтры).
- Доступность: приоритет в outline не только цветом _(если используется цвет — дублировать текст/бейдж)_.
- Тёмная тема: цвета бейджей должны читаться в light и dark (`var(--…)`).

## 8. Критерии приёмки (Acceptance Criteria)

### AC-1. Редактирование приоритета

| ID | Given / When / Then |
|----|---------------------|
| AC-1.1 | **Given** выбран узел, **When** в карточке выбран приоритет _[1/2/3]_, **Then** у узла `priority` = выбранное значение, данные сохраняются. |
| AC-1.2 | **Given** у узла задан приоритет, **When** снять приоритет _(если разрешено)_, **Then** `priority = null`. |
| AC-1.3 | **Given** новый узел (Tab/Enter), **When** открыть карточку, **Then** приоритет = `null`. |

### AC-2. Отображение

| ID | Given / When / Then |
|----|---------------------|
| AC-2.1 | **Given** узел с приоритетом, **When** смотреть Outline, **Then** приоритет виден в формате _[из FR-2]_. |
| AC-2.2 | **Given** узел с приоритетом, **When** вкладка «Карта», **Then** приоритет виден на блоке узла. |
| AC-2.3 | **Given** `priority = null`, **When** Outline/Карта, **Then** _[не показывается / показывается «—»]_. |

### AC-3. Фильтрация

| ID | Given / When / Then |
|----|---------------------|
| AC-3.1 | **Given** узлы с разными приоритетами, **When** выбран фильтр _[1/2/3]_, **Then** видны только подходящие узлы и их предки-контекст. |
| AC-3.2 | **Given** активны фильтры «Ответственный» + «Приоритет», **When** применить, **Then** совпадение по **всем** активным фильтрам (AND). |
| AC-3.3 | **Given** фильтр по приоритету, **When** «Сбросить», **Then** приоритетный фильтр снят вместе с остальными. |
| AC-3.4 | **Given** нет узлов по фильтру, **When** смотреть панель, **Then** «Нет результатов». |

### AC-4. Данные

| ID | Given / When / Then |
|----|---------------------|
| AC-4.1 | **Given** старый `mindmap.json` без `priority`, **When** загрузка, **Then** без ошибок, `priority = null`. |
| AC-4.2 | **Given** изменение приоритета, **When** перезагрузка страницы, **Then** значение сохранено. |

## 9. Вне скоупа v1

- автоматический приоритет по deadline;
- массовое изменение приоритета для поддерева;
- сортировка дерева по приоритету;
- экспорт/импорт приоритета в календарь.

---

## 10. Проверочный сценарий (smoke)

1. Создать узел → в карточке задать приоритет `1` → в Outline и на Карте виден бейдж/подпись.
2. Задать разным узлам приоритеты 1, 2, 3 → фильтр «Приоритет: 1» → остаются только нужные ветки.
3. Совместно с фильтром «Статус: New» → пересечение условий.
4. Сбросить фильтры → снова видно всё дерево.
5. Открыть старую карту без поля `priority` → редактор не падает.
