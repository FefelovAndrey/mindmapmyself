# BRD — Business Requirements Document
## Mind Map Editor (задачи RULI)

**Версия:** 1.1  
**Дата:** 23.06.2026  
**Автор:** Андрей Фефёлов

---

## 1. Контекст и цель

Текущий инструмент — MindManager (.mmap). Требуется собственный редактор для управления иерархическими задачами команды RULI, не зависящий от лицензий MindManager и расширяемый под нужды проекта.

**Цель:** создать веб-приложение, позволяющее просматривать, редактировать и фильтровать дерево задач с атрибутами, с горячими клавишами, аналогичными MindManager.

---

## 2. Функциональные требования

### 2.1. Структура узлов

- Вложенность узлов не ограничена
- Каждый узел имеет иерархический номер, вычисляемый автоматически по схеме: `1` → `1.1` → `1.1.1` и т.д.
- При добавлении, удалении или перемещении узла нумерация пересчитывается автоматически

### 2.2. Атрибуты узла

| Атрибут | Обязательный | Тип | Ограничения |
|---------|:---:|-----|-------------|
| Номер | да | строка, авто | вычисляется из иерархии |
| Наименование | да | строка | — |
| Описание | нет | строка | до 2000 символов |
| Ответственный | нет | строка | — |
| Статус выполнения | нет | enum | `New`, `Done`, `Cancelled` |
| Срок выполнения | нет | дата | формат YYYY-MM-DD |

> Другие атрибуты планируются к добавлению в следующих версиях.

### 2.3. Визуальное отображение

- В дереве (outline) отображаются: Номер, Наименование, Ответственный, Статус, Срок выполнения
- Описание (Атрибут «Описание») отображается **отдельным блоком** в карточке узла, не в строке дерева
- При выборе узла открывается карточка со всеми атрибутами для редактирования

### 2.4. Создание и редактирование узлов

Горячие клавиши должны соответствовать логике MindManager:

| Клавиша | Действие |
|---------|----------|
| `Enter` | Добавить узел на том же уровне (после поддерева текущего) |
| `Shift+Enter` | Добавить узел на том же уровне (перед текущим) |
| `Tab` | Добавить дочерний узел (вложить) |
| `Delete` | Удалить текущий узел вместе со всеми потомками |
| `F2` / двойной клик | Редактировать название inline |
| `Enter` (в режиме редактирования) | Сохранить название |
| `Escape` (в режиме редактирования) | Отменить редактирование |
| `→` / `←` | Развернуть / свернуть ветку |

**Ограничения для корневого узла:**
- `Enter` на корне = редактировать название корня
- `Delete` на корне = запрещён
- `Shift+Enter` на корне = игнорируется

**Реализация `Tab`:** клавиша перехватывается с `preventDefault()` только когда фокус находится на узле дерева, чтобы не конфликтовать с системной навигацией в полях ввода.

### 2.5. Фильтрация

- Фильтрация в outline по полям: **Ответственный** и **Статус**
- Фильтры реализованы как выпадающие списки со значениями из данных
- При активном фильтре: совпадающие узлы выделены, родительские узлы остаются видимыми в приглушённом виде (контекст иерархии сохраняется)
- Нумерация при фильтрации остаётся оригинальной (не пересчитывается)
- Кнопка «Сбросить» снимает все фильтры

---

## 3. Нефункциональные требования

- Приложение работает локально, не требует интернета
- Запуск командой: `npm run dev` → открыть браузер на `localhost:3000` вручную
- Данные сохраняются в JSON-файл на диске
- Изменения сохраняются автоматически (без явного нажатия «Сохранить»)
- Приложение должно корректно работать при числе узлов до 500
- Конкурентная запись файла не поддерживается — приложение рассчитано на одного пользователя

---

## 4. Миграция данных

- Разовый импорт из файла `TasksRULI_23062026.mmap` (формат MindManager, ZIP-архив, 103 узла)
- Файл находится в папке проекта `MindMap/`
- Из файла извлекается иерархия узлов (поле `PlainText`)
- Атрибуты (Ответственный, Статус, Срок) при импорте **не парсятся** — заполняются вручную в новом редакторе
- После импорта и заполнения атрибутов `.mmap` больше не используется

---

## 5. Вне области (не входит в v1.0)

- Радиальная (mind map) визуализация
- Drag-and-drop перетаскивание узлов
- Синхронизация с Yandex Tracker
- Экспорт обратно в `.mmap`
- Совместное редактирование
- Gantt, Kanban-представления
